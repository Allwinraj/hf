JOURNEY 5 — Purchase requisitions from unread email (Procure-to-Pay)
Owner review pack  ·  try this in Architect; mark anything that does not match

What this proves
----------------
Same Nexus Architect as bank recon and invoice match. Different process.
Working file is a sample .eml (body + optional PDF). Run reads live unread Gmail,
keeps PR/PO subjects, drafts replies vs policy. A human Send on the dashboard
is required — the pipeline never SMTP-sends on its own.

CSV / XLSX journeys are unchanged. Mailbox canvas only appears when the working
file is .eml. Extraction reads that mail; it is not hardcoded to laptops or Bengaluru.

User: Procurement / AP, professional services.
Goal: Turn unread PR-request mail into policy-checked draft replies; send only after approval.

v1 note: IMAP unread + dashboard SMTP after Send. No ERP write-back, Slack, or auto-send.

  1.  I'm a procurement analyst supporting Digital Technology purchases.

  2.  Professional services — India offices, INR.

  3.  Read new purchase-request emails, check them against policy, and draft replies I can send myself.

USE CASE

  4.  Purchase requisitions from email. Read unread inbox mail whose subject looks like a PR or purchase request, extract the ask from the body and any attached spec PDF, judge against our purchase policy, and draft a reply. Nothing should go out until I click Send on the dashboard.

INPUT FILES

  5.  Yes — I have a sample PR email saved as an .eml.

      [Attach]  PR_Request_New_Joiner_Laptops_Bengaluru.eml

KNOWLEDGE / POLICY

  6.  Yes — attaching our IT / purchase policy.

      [Attach]  IT_Purchase_Policy.pdf

INTERVIEW (typical answers — wait for Nexus, then paste)
Nexus should ask about this mail (qty, location, cost centre, budget, PDF spec),
not about matching columns.

  7.  Use the body for quantity, location, cost centre, due date and budget. Use the PDF for device spec, catalogue, supplier and substitution rules. If they differ, the PDF wins.

  8.  Fail the PR if it is not a catalogue item, the supplier is not approved for IT hardware, the total including tax and delivery is over the stated budget, or they substituted without Digital Technology approval. Warn-only is not enough for those four.

  9.  Draft from Nexus Procurement, plain professional tone, reply to the requester. A human must click Send or Don't send on the dashboard — never auto-send.

 10.  Same layout for other unread PR subjects (other offices or item types). Skip mail whose subject is not a PR or purchase request.

CONFIRM + SAVE + LIBRARY RUN

      [Click] Confirm pipeline
      Open the Mailbox ingest node — Gmail IMAP/SMTP fields should already be filled.
      [Click] Save
      You land in Super Agents library.
      [Click] Run
      Dashboard: unread fetched, PR kept, skipped noise, waiting send.
      Table of drafts: Send all / Send / Don't send.
      After Send, that row is sent via SMTP and marked sent.
